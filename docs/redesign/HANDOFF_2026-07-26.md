## The single most useful thing to know

**Two of five bug reports in this round were a stale JavaScript bundle.**
WKWebView keeps the previous JS across a native rebuild unless the app is
force-quit and relaunched, and the web build is pinned by a service worker.

So the app now reports its own identity in **Settings → About**:

- **Build** — short git SHA, `+` if the tree was dirty when built
- **Platform** — `iPad app on Mac` vs `iOS/iPadOS`, plus the touch-point count
  (native only)

**Before debugging any report, confirm the build id.** Before debugging anything
keyboard- or layout-shaped on a Mac, confirm the Platform line. Both exist
because getting them wrong is invisible and has already cost two rounds.

To put a specific build on the Mac:

```
npm run build:native                       # web build + CSP/viewport inject + cap sync
open ios/App/App.xcodeproj                 # then press Cmd-R
```

`xcodebuild -destination 'platform=macOS,variant=Designed for iPad'` builds fine
but **cannot be launched from the CLI** — `open` rejects the iphoneos bundle and
`devicectl` cannot address the local Mac. Xcode's Run is the only path.

**`npm run build:native` leaves `dist/` unsafe to deploy.** It injects the native
CSP and `user-scalable=no` into `dist/client/index.html`. Deploying that would
ship a locked viewport to the web and kill pinch-zoom. Always `npm run build`
before `wrangler deploy`. This was caught mid-deploy once.

## What shipped this round

Merged as PR #11 (`bd367c6`), worker version `e4f83dc8`, plus follow-ups.

**Security**
- Password change now revokes this device's passkey and Face ID unlock
  (FULL_AUDIT_2 S1 — the audit's one real security gap). Runs strictly after
  finalize and best-effort: a server rejection must not revoke.
- react-router advisory cleared, plus eight others. Migrated `react-router-dom` →
  `react-router` v8 (14 import sites); react 19.2.8.

**Accessibility / theming** — the largest change
- The accent tokens are split **by the surface they land on**, not by shade:
  `--color-sax` / `-sax-ink` / `-sax-on-orbit` / `--color-on-sax`, and the same
  shape for crane and crease. One token could not be both a fill carrying dark
  ink and legible text on parchment; Vellum and Paper had "fixed" it in opposite
  directions and both were wrong. **Do not re-merge them.**
- Vellum's `--color-orbit` was a light parchment while `SafetyNumberDialog`
  hardcoded `text-white`, so the safety-number screen — the MITM check — rendered
  at **1.27:1**. Now 13.17:1, verified in a real browser across all five themes
  and confirmed on device.
- `test-ui/themeContrast.test.ts` computes every pairing per theme from the token
  values parsed out of `src/index.css`, composites alpha before the WCAG maths,
  and adds four repo-wide greps asserting components actually use the tokens.
  Evidence table in `docs/redesign/verify/FULL_AUDIT_2_CONTRAST_VERIFY.md`.
- **No opacity modifier on text that must clear 4.5.** Tailwind v4 compiles `/NN`
  to `color-mix(in oklab, …)`, which does not match an sRGB alpha model and reads
  optimistic. De-emphasis uses precomputed `-dim` tokens instead.

**Bugs found while doing the above**
- Settings was **unreachable** on native at >= 900px with a conversation open —
  a state with no exit, shipping on iPad in landscape. Chrome rules moved out of
  JSX into `src/lib/chatChrome.ts` as predicates; a test walks all 48 states.
- Voice notes were **unplayable on every Apple device** when recorded in Chrome.
  `MediaRecorder` with no mimeType yields WebM/Opus, which Safari cannot decode.
  And asking for a bare `audio/mp4` is not enough — measured in a real Chromium,
  that yields `audio/mp4;codecs=opus`. `src/lib/audioFormat.ts` names
  `mp4a.40.2` explicitly. **Do not simplify it back to the container.**

**Diagnosability**
- Worker observability enabled; APNs failures now log status + Apple's `reason`.
  Previously anything that was not 200/410 was swallowed silently.

## Open, with what is already ruled out

### 1. The ghost row on "My Mac (Designed for iPad)" — THREE failed fixes

**Symptom:** a duplicated, offset copy of the bottom row (composer / search bar)
painted on top of the real one. Appears on focusing a text field — the composer,
"New message", "Search locally" — clears when focus moves. **Native only**: does
not reproduce in a Mac browser at the same window size.

**Ruled out, do not re-try:**
- Not the `transition: height` on the shell alone (gated it; no change).
- Not the bottom row being clipped by the window — that reading was wrong and
  was corrected by Anmol; it is an overlay, not clipping.
- Not `navigator.maxTouchPoints > 0` as a discriminator for "iPad app on Mac" —
  gating on it changed nothing, which is itself evidence that it does not
  discriminate here.

**Current state:** the keyboard compensation is gated on
`ProcessInfo.isiOSAppOnMac`, injected natively by `MainViewController` as
`window.__flatfoldIsIOSAppOnMac` and read via `isIOSAppOnMac()` in
`src/lib/platform.ts`. **As of the last report the ghost was still present**, but
it is unconfirmed whether that build included the fix, and the About → Platform
line now answers that directly.

**Next diagnostic, before any fourth fix:** read About → Platform.
- `iOS/iPadOS` on a Mac ⇒ detection is broken; fix that, nothing else.
- `iPad app on Mac` ⇒ the keyboard theory is **dead**; stop tuning it.

If the theory is dead, the untested suspects are (a) WKWebView's own
scroll-to-reveal on input focus moving the whole scroll view under an
`overflow-hidden` shell — try `bridge?.webView?.scrollView.isScrollEnabled = false`
in `MainViewController`, since the app manages its own scrolling; and (b) the
`animate-*` classes. Debug builds keep Web Inspector, so **Safari → Develop →
[Mac] → the FlatFold WebView** gives the real console and a live element
inspector. Use it before guessing again.

### 2. Microphone on Designed-for-iPad

`getUserMedia` fails; no TCC prompt appears. **Ruled out:** the WebView layer —
Capacitor implements `requestMediaCapturePermissionFor` and grants
unconditionally, and `MainViewController` does not override the UI delegate. So
macOS is declining to prompt. The likely fix, `com.apple.security.device.audio-input`,
is a **Catalyst-only** sandbox entitlement, and Catalyst is blocked (below).
Recommendation: do not spend more here while the target is passthrough.

### 3. Voice notes still reporting "cannot decode format"

That string is the new instrumentation in `VoiceNote.tsx` and it **names the
format in parentheses**. Get that value before doing anything. Old notes encoded
as Opus can never be fixed — nothing can re-encode bytes already sent. Only a
note recorded *after* `b068103`, in a browser that can record `mp4a.40.2`, tests
the fix. `MediaAttachment` separately distinguishes a download failure now,
including the single-fetch case below.

### 4. macOS — the big decision

Mac Catalyst is **blocked**, not merely hard: `Capacitor.xcframework` ships only
`ios-arm64` and `ios-arm64_x86_64-simulator`. There is no `maccatalyst` slice, so
it cannot link. Recorded on branch `spike/mac-catalyst` (`5bc798e`), not merged.

`docs/DESKTOP_SHELL_OPTIONS.md` lays out five options. The short version: decide
it on **secure storage**, because that is the expensive-to-reverse part. Tauri's
official secret store (Stronghold) is not an OS keychain, and OS-keychain access
is via single-maintainer community plugins — which would move master-key custody
off the Secure Enclave. Leaning B (CocoaPods → Catalyst, validate cheaply first)
or E (descope desktop honestly), not a Tauri migration.

## Things that will waste your time if you do not know them

- **Attachments download exactly once.** `ackMediaFetched` deletes the R2 copy as
  soon as any device fetches it, so a second device legitimately cannot get it.
  Looks exactly like corruption. The UI now says so.
- **The iOS Simulator cannot reach a logged-in state** — Argon2 and HPKE WASM
  segfault. Real hardware only.
- **`git checkout` will fight you**: the working tree carries three long-standing
  uncommitted files (`.gitignore`, `App.xcscheme`, `CapApp-SPM/Package.swift`)
  plus untracked `brand/` assets. They are Anmol's. Do not stash or commit them.
- **Commit by explicit path**, never `git add -A`.
- Two vitest projects: `worker` (workerd, no IndexedDB, `hash-wasm` banned) and
  `ui` (jsdom, `fake-indexeddb`). Put a test in the wrong one and it fails
  confusingly.
- 662 tests, `tsc -b` and eslint clean. Keep it that way.

## House rules that were load-bearing this round

- **Watch the test fail first.** The Settings dead-end, the S1 revocation and the
  contrast failures were each reproduced before being fixed. The contrast test
  reproduced the audit's pre-fix table exactly, which is what proved the maths.
- **A passing unit test does not prove the app uses the code.** Four repo-wide
  greps exist because 145 passing colour assertions proved only that the
  stylesheet *would* pass. The dot regression got in through exactly that gap.
- **Verify in the real engine.** The contrast numbers were re-measured in Chrome
  via static per-theme pages; the codec fix was proven by recording a real
  MediaRecorder stream. Both overturned a conclusion reached from arithmetic.
- **Say what is unverified.** Several fixes here are hypotheses that could not be
  reproduced locally, and they say so in their commit messages.
