## The one that matters for macOS: no `navigator.mediaDevices`

**Measured on a signed Catalyst build with `com.apple.security.device.audio-input`
in the binary: `secure: yes`, and `mediaDevices` still absent.**

So this is a WKWebView limitation that survives the move to a real Mac app. It
was never only about the iPad passthrough, and the "Catalyst-only entitlement"
theory that sat in these docs for days is wrong for BOTH shells.

Consequence: **`FlatFoldAudioPlugin` must stay.** The strongest argument for the
migration was that Catalyst would delete it; that half is false. Recording on Mac
goes through the native plugin either way.

## Finishing macOS — what is actually left

1. **Verify the Catalyst app end to end.** Login, messages, voice-note record →
   send → play, attachments. Only "builds, launches, sends messages" is proven.
2. **Voice-note playback on Mac is UNVERIFIED** after the shared-player revert
   (`42eab9c`). It works on iOS. The Mac was never re-tested after the revert
   because the Catalyst work started.
3. **Is the ghost row gone?** It should be — Catalyst has real Mac text input, and
   the hack (`MainViewController.installMacInputBarHide`) targets an iPadOS input
   host view that should not exist there. If confirmed gone, DELETE the hack.
4. **`@capacitor/filesystem` is excluded on Catalyst**, so native file save is
   missing there. Its `IONFilesystemLib` is a binary-only pod
   (`vendored_frameworks`, ios slices only, no source in the pod) and cannot be
   rebuilt for Catalyst. On a real macOS WKWebView `<a download>` may work
   directly — untested, and it is the natural replacement.
5. **Signing and distribution** are untested beyond a local signed build. Mac App
   Store vs Developer ID is an open decision.
6. **Catalyst can be driven from the CLI.** Unlike "Designed for iPad" — which
   `xcodebuild` refuses outright ("UI tests are not supported on My Mac (Designed
   for iPad)") — a Catalyst app can be launched and UI-tested. There is an
   `AppUITest` scheme and a launch-only `testMacSmoke`. **Set this up early**: it
   removes the human round-trip that made this round so slow.

## Build mechanics (all in `ios/CATALYST.md`)

- **Open `App.xcworkspace`, never `App.xcodeproj`.** The project cannot see the
  pods; the error is `No such module 'Capacitor'`. Quit Xcode when switching —
  they have separate DerivedData and the stale one keeps reproducing the error.
- **The pod set is stateful.** `pod install` = iOS; `FLATFOLD_CATALYST=1 pod
  install` = Catalyst. Wrong one → `Unable to resolve module dependency:
  'IONFilesystemLib'`. Check with `cat ios/App/Pods/.flatfold-pod-mode`.
- `ENABLE_USER_SCRIPT_SANDBOXING = NO` and `ENABLE_MODULE_VERIFIER = NO` (pods)
  are both set. The first fails as rsync `Operation not permitted`; the second
  only on SIGNED builds, so an unsigned build passes and a signed one fails on
  unchanged code.

## Ruled out — do not re-test

**Voice notes** (full detail in `docs/redesign/verify/MAC_VOICE_NOTES.md`):
the codec (`mp4a.40.2` is correct and required), the container (AVAudioFile
parses it), finalization (`stop()` is async — fixed via the delegate), the input
device, the base64 bridge (it wedged the WebContent process; now a path read via
`convertFileSrc`), `res.ok` on a custom-scheme fetch (WKWebView replies with a
plain URLResponse, so status is 0 on success), and AVAudioSession — left active,
deactivated, and restored-to-playback, with the same result each time.

**Mac shell**: Catalyst is not blocked by Capacitor's source — every pod
typechecks for `-macabi` with a delta of zero against iOS. Only the prebuilt
SwiftPM xcframework was blocked.

## Bugs found that were NOT platform-specific

Worth knowing because they were live in shipping code:

- **CSP `connect-src` was missing `blob:`**, so `fetch()` of a blob URL failed on
  every platform. The waveform decode had never worked anywhere. `img-src` and
  `media-src` both had `blob:`, which is what stopped anyone noticing.
- **`isInspectable = false` never ran on iPhone** — it was nested inside a
  Mac-only branch, so the Web Inspector hardening was not applied on the platform
  that ships.
- **Debug instrumentation shipped in Release**: `nativeLog` made a Capacitor
  bridge round-trip per voice note. Now gated on `window.__flatfoldDebug`.
- **Per-note `AudioContext`** exhausted WebKit's cap and surfaced as a codec
  error. Now one shared context, decodes capped at 2 with a timeout.

## Process notes — these cost more than the bugs

- **Unit tests cannot see a render loop or a detached element.** An uncached
  `useSyncExternalStore` snapshot took the whole app down while 700 tests passed.
  `test-ui/voiceNoteRender.test.tsx` now renders the component; extend it rather
  than adding more unit tests for UI behaviour.
- **The web build runs in a normal browser.** Most failures this round were
  web-layer and locally reproducible. Only `mediaDevices` absence and the media
  resource pool genuinely need WKWebView.
- **`BUILD SUCCEEDED` means only that what you fed the compiler compiled.** An
  edit silently dropped five pods and the build still went green. On a migration,
  assert the dependency count.
- **A theory recorded as fact gets believed.** "Blocked behind a Catalyst
  entitlement" and "Catalyst is impossible" were both wrong, both stated
  confidently, and both steered work for days. Write down what was measured, in
  the same sentence as the claim.
