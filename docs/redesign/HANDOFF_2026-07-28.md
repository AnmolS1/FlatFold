## The diagnosis, settled

> On **Mac Catalyst**, WKWebView grants media loaders in a window tied to **page
> load**, capped at **~30**, and never reclaims them within that page. A new
> page load reopens the window; a React remount does not.

Consequences: the tail of a long conversation never plays, and a newly arrived
note never plays until relaunch. ~60 trials, five conditions, interleaved, with
enforced cooldowns.

**iOS is NOT affected** — verified 2026-07-28 on a real iPhone 14 Plus: every
note in the same 40-note conversation plays. So iOS, the shipped target, is not
broken, and native playback is gated to Catalyst only.

**Do not re-test** the refuted list in FINDINGS §2 (element-count ceiling,
capacity, batch, containment, provenance, service worker, container/codec, blob
revocation, audio session, the fixture). Each cost at least a build/reproduce
cycle; several cost a night.

## Where the fix is

Playback moves out of the web view, exactly as recording already did. A
from-scratch native app was considered and rejected — it would mean
reimplementing X3DH, the ratchet, sender keys and the keystore in Swift.

**DONE — `bf9a408`, verified in `verify/NATIVE_AUDIO_PLAYBACK.md`.** 42 of 42
notes play across three fresh launches, with zero `<audio>` elements on the
platform; a note produced during the run plays immediately with no reload and no
re-unlock; pause A / play B / return to A resumes to the sample. iOS re-verified
by hand on a real iPhone after the element branch was rewritten.

Built from:
- Swift: `playNote` / `pauseNote` / `seekNote` / `stopNote` / `getPlaybackState`,
  plus `audioProgress` (~10 Hz) and `audioEnded` via `notifyListeners`.
  `AVAudioPlayer(data:)` — plaintext never touches disk, which is a privacy
  improvement over the recorder's temp file, not just an API preference.
- JS: `nativePlayer` in `src/lib/nativeAudio.ts`.

- `VoiceNote.tsx`, split into two backends behind one look. The native branch
  renders **no** `<audio>`; that absence IS the fix, since even an unplayed
  element takes a grant.
- `src/lib/voicePlayer.ts` — the transport store. Keys positions on
  `MediaRef.id`, NOT the blob URL, which `MediaAttachment` revokes and recreates
  per mount. Subscribes per note, because progress ticks at 10 Hz.
- `audioInterrupted` wired. See the caveat below.
- `src/components/debug/` and the `--audio-experiment` conditions deleted;
  `--verify-audio` replaces them.

### What is still open on this

- **The interruption path is unverified.** Eight system sounds played through
  another process during a sweep and nothing interrupted — with
  `.mixWithOthers`, other audio MIXES, and that option is load-bearing for a
  separate reason (`restorePlaybackSession`). The observer is wired for the
  interruptions that do fire (a call, an app taking the session exclusively) and
  that branch has never run. Do not make it observable by dropping the option.
- **Playback is enabled on BOTH Mac shells**, deliberately and by judgement, not
  by measurement: the loader cap was measured on Catalyst only. The reasoning is
  in `FlatFoldAudioPlugin.isMacShell` — same WKWebView, same OS, and a native
  player cannot be worse than an element that will not load. If the "Designed for
  iPad" build ever misbehaves, that gate is the first place to look.
- **Nothing stops playback when the conversation is closed.** A note keeps
  playing natively if you navigate away mid-note. Not wired to unmount on
  purpose — unmount also fires on scroll if the list ever virtualises.

## Also fixed this round

- **The recorder was inert on Catalyst** (`31e6b70`). It gated on
  `ProcessInfo.isiOSAppOnMac`, which is **false** under Catalyst — the two flags
  are not synonyms. Recording now verified working there.
- **Audio session restored on the success path** — it lived only in `cleanUp()`,
  which success skips, so a recording that *worked* left the session in
  `.playAndRecord` while one that failed tidied up.
- **The biometric label** reads `LAContext.biometryType` instead of assuming
  Face ID (`341f8a3`).
- Microphone release confirmed from the CoreAudio HAL, not from an API
  returning cleanly.

## Build mechanics

```bash
# Web bundle. NOT `npm run build:native` — it runs `cap sync`, which silently
# flips the pod mode to iOS and makes the NEXT Catalyst build fail with a
# misleading `Unable to resolve module dependency: 'IONFilesystemLib'`.
npx vite build && node scripts/gen-sw-manifest.mjs \
  && node scripts/inject-native-csp.mjs && npx cap copy ios

cat ios/App/Pods/.flatfold-pod-mode      # must say `catalyst`

cd ios/App
osascript -e 'quit app "App"'            # WKWebView keeps old JS otherwise
xcodebuild -workspace App.xcworkspace -scheme App \
  -destination 'platform=macOS,variant=Mac Catalyst' \
  -derivedDataPath build/DDcat -configuration Debug build
open -n build/DDcat/Build/Products/Debug-maccatalyst/App.app
```

Building for a real iPhone flips the pod mode; run `FLATFOLD_CATALYST=1 pod
install` before the next Mac build. Pod mode is currently **catalyst**.

Read instrumentation with:
```bash
/usr/bin/log show --last 4m --info --debug \
  --predicate 'subsystem == "dev.flatfold"' --style compact
```

- `NSLog` produces **nothing** from this target outside Xcode — use `os.Logger`,
  and every interpolation needs `privacy: .public` or it logs `<private>`.
- `/usr/bin/log`, not `log` — shadowed in this zsh.

## The trial harness (keep it)

`scripts/audio-trial.sh`, `audio-batch.sh`, `audio-analyze.py`. Conditions are
launch arguments, so one build runs them all. It enforces a **cooldown gate**
(the resource is reclaimed over minutes while a build-relaunch cycle is ~2
minutes) and **auto-discards trials without a baseline**. Both rules exist
because violating them voided entire nights.

Also: don't rebuild mid-batch (it swaps the `.app` in-flight trials launch), and
keep other media closed on the Mac — the pool is system-wide and a video playing
contaminated a whole overnight run.

## Open, not blocking

- The **reload result is n=1** and unreplicated. It matters only if the native
  path fails; otherwise it becomes moot.
- **Duration is overstated ~27%** — `rec.currentTime` is sampled before
  `stop()`. It is baked into the `MediaRef`, so receiving devices show it too.
  Native playback fixes the *playing* device via `AVAudioPlayer.duration`; the
  recorder fix is separate.
- **Waveforms are flat on Mac** (Web Audio `decodeAudioData` fails there,
  cosmetic and pre-existing). The durable fix is peaks computed by the sender
  and shipped in the `MediaRef` — a payload-schema change, needs Anmol's
  sign-off and a backward-compatible optional field.
- `@capacitor/filesystem` is excluded on Catalyst, so native file save is
  missing there; `<a download>` may work and is untested.
- Signing and distribution for macOS are undecided.

## Constraints

Frozen: `src/crypto/**`, `src/keystore/**`, `worker/**`, the ratchet region of
`src/lib/messaging.ts`. Public repo — no secrets in commits. Decrypted audio is
plaintext of an E2EE message: keep it in memory, never write it to disk, never
log it by content. Commit by explicit path; never `git add -A`. Do not commit
`App.xcscheme`, `AppUITests.xcscheme`, `CapApp-SPM/Package.swift`, or `brand/`.
Watch a regression test fail against pre-fix code before trusting it.
